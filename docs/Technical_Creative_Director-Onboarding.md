Your job:

Build the 3-room slice before the MVP.
It should prove: combat readability, one package choice, one graph mutation, one consequence, one mini-postmortem. If that loop sings, the rest has a spine.

Prototype the graph-effect framework early.
This is the real risk. If packages become bespoke code, the design will bog down. Keep effects data-driven and composable.

Treat visual polish as a reward, not the first task.
The mockups are seductive. Get graybox combat plus graph legibility working first, then pour the CRT glow over something alive.

Decide graph-scale interaction soon.
Inspection-only vs pause-based triage vs active graph encounters changes UI, input, and engineering assumptions.

Keep the MVP toy-sized but story-rich.
You do not need a real package simulator. You need 6 to 10 interactions that produce stories players can explain.

The strongest north star remains: “I made a reasonable choice, it helped, then it came back later in a way I understand.” If the first playable delivers that, you’re cooking.
